## 修复宏重定义

- 问题：`build.bat` / `CMakeLists.txt` 用 `-D` 将 `WIN32_LEAN_AND_MEAN`、`NOMINMAX` 定义为 `1`，`src/common.h` 又无条件定义为空，导致宏重定义告警/错误。
- 作用：`WIN32_LEAN_AND_MEAN` 精简 windows.h；`NOMINMAX` 避免 Windows 的 min/max 宏与 `std::min/std::max/std::clamp` 冲突（代码中确认无裸 min/max 调用）。
- 方案：`common.h` 中改为 `#ifndef` 守卫并统一定义为 `1`；从 `build.bat`（两处）和 `CMakeLists.txt`（主程序 + 测试目标）移除重复定义，形成单一数据源，同时兼容外部传入的 `-D`。

## 运行时打包流程（静态链接 + 精简包）

- 背景：分发到其他电脑无窗口，原因是 exe 动态依赖 libstdc++-6.dll / libgcc_s_seh-1.dll / libwinpthread-1.dll。
- `build.bat`：`pick_clang`（clang + MinGW）与 `pick_gxx` 均改为 `-static -static-libgcc -static-libstdc++`，移除 `-nodefaultlibs` 与动态 `-lpthread`；新增 `package` 参数：构建后清空 `.neoide\dist`，仅复制 `NeoIDEs.exe`，生成 `.neoide\NeoIDEs.zip`（用系统归档命令，非 GNU tar 的 zip）。
- `CMakeLists.txt`：MINGW 下 `target_link_options` 加 `-static -static-libgcc -static-libstdc++`，移除动态 `stdc++/winpthread` 链接；新增 `package` 自定义目标（`cmake -E rm/make_directory/copy/chdir tar --format=zip`），产物在 `${CMAKE_BINARY_DIR}/dist` 与 `NeoIDEs.zip`。
- 验证：`build.bat package` 与 CMake `package` 目标均成功；objdump 确认两种产物都不再导入 MinGW 运行库 DLL（仅系统 DLL 与 UCRT api-ms-win-crt-*）；dist 与 zip 均只含 `NeoIDEs.exe`；从 dist 目录直接启动 exe 窗口正常。
- 注意：UCRT 仍为系统依赖，Win10/11 自带；Win7/8.1 需安装通用 C 运行时更新（KB2999226）。
